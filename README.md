## 👋 Bienvenue

MC88 STORE est un fichier HTML unique. Il lit les releases d'un dépôt GitHub et affiche chaque application sous forme de carte. Aucune base de données n'est nécessaire. Publiez une nouvelle release, le store se met à jour automatiquement.

---

## ✨ Ce que vous trouverez

**Lecture automatique des releases.**  
Le store charge un fichier releases.json ou interroge l'API GitHub. Chaque release avec un fichier .apk devient une carte.

**Huit thèmes visuels.**  
Souk, Aegean, Wave, Sakura, Terminal, Escape, Pixel et Dusk. Un seul bouton fait défiler les thèmes. Le choix est sauvegardé.

**Recherche et tri.**  
Cherchez par nom, description ou tag. Triez par date, nom, taille ou nombre de téléchargements.

**Catégories automatiques.**  
Les tags écrits dans le corps de la release deviennent des filtres. Utilisez « Tags: games, tools » ou « #games #tools ».

**Application mise en avant.**  
Ajoutez « featured: true » dans le corps d'une release pour l'afficher en grand en haut de la page.

---

## 🧭 Comment ça marche

**1. Créez une release sur GitHub.**  
Ajoutez un fichier .apk en pièce jointe.

**2. Écrivez une description dans le corps de la release.**  
La première ligne devient la description. Les tags deviennent des catégories.

**3. Ouvrez le fichier HTML.**  
Le store charge les releases et affiche les applications.

**4. L'utilisateur clique sur « Download APK ».**  
Le fichier se télécharge directement depuis GitHub.

C'est tout. Aucun serveur n'est nécessaire.

---

## 🛠️ Petits coups de main

**Faut-il une base de données ?**  
Non. Tout vient des releases GitHub.

**Comment ajouter une application ?**  
Publiez une nouvelle release avec un fichier .apk. Le store la détecte au prochain chargement.

**Comment marquer une application comme « en vedette » ?**  
Ajoutez « featured: true » dans le corps de la release.

**Que se passe-t-il si l'API GitHub est limitée ?**  
Le store affiche un message d'erreur. Attendez une minute puis rechargez.

## 👋 Welcome

MC88 STORE is a single HTML file. It reads the releases of a GitHub repository and displays each app as a card. No database is required. Publish a new release, and the store updates automatically.

---

## ✨ What you'll find

**Automatic release loading.**  
The store loads a releases.json file or queries the GitHub API. Each release with an .apk file becomes a card.

**Eight visual themes.**  
Souk, Aegean, Wave, Sakura, Terminal, Escape, Pixel and Dusk. A single button cycles through themes. The choice is saved.

**Search and sort.**  
Search by name, description or tag. Sort by date, name, size or download count.

**Automatic categories.**  
Tags written in the release body become filters. Use "Tags: games, tools" or "#games #tools".

**Featured app.**  
Add "featured: true" in a release body to show it large at the top of the page.

---

## 🧭 How it works

**1. Create a release on GitHub.**  
Attach an .apk file.

**2. Write a description in the release body.**  
The first line becomes the description. Tags become categories.

**3. Open the HTML file.**  
The store loads the releases and displays the apps.

**4. The user clicks "Download APK".**  
The file downloads directly from GitHub.

That's it. No server needed.

---

## 🛠️ A little help

**Do I need a database?**  
No. Everything comes from GitHub releases.

**How do I add an app?**  
Publish a new release with an .apk file. The store detects it on the next load.

**How do I mark an app as "featured"?**  
Add "featured: true" in the release body.

**What happens if the GitHub API is rate-limited?**  
The store shows an error message. Wait a minute and reload.
